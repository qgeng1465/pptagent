# 内容诚实协议（Honesty Protocol）

> 2026-08-07 用户指令：**"不能编东西，就是依赖用户上传的 PPT 模板和用户上传的
> 文档和交互信息来改 PPT（从模板上来改）；可以有一定的联网思考，但是仅仅是在
> 用户没有 cover 到的信息来补充，而且补充的信息一定要是真的。"**
> 本文档把这条指令固化为管线铁律，任何一次生成/修改必须遵守。

## 一、内容来源优先级（L1 > L2 > L3 > L4）

| 级别 | 来源 | 用途 | 可信度 |
|---|---|---|---|
| **L1** | 用户上传的 PPT 模板（如 `组会模板.pptx`） | 版面身份（字体/配色/版式）；模板幻灯片里**已有文字**可直接作为内容 | 最高 |
| **L2** | 用户上传的文档（研究计划/论文/数据/内容图） | 研究内容、实验数据、技术路线 | 最高 |
| **L3** | 交互信息（对话里用户明确告知的事实） | 补充 L1/L2 未覆盖的个人/单位信息 | 高 |
| **L4** | 联网检索（可选） | **只补 L1-L3 都未覆盖的缺口**，且必须是可核实的事实 | 中，需标注来源 |

**铁律：没有 L1-L4 任何来源支撑的内容 = 不存在，禁止出现。**
编造 = 在来源之外臆造数字/成果/头衔/经历。所有 L1-L3 无法覆盖的字段一律用
`××` / `（待填）` 占位，绝不填"看起来合理"的编造值。

## 二、哪些属于"编造"（必须清除）

- 个人成果数字：论文数、被引量、专利数、主持/参与项目数、奖项数——**用户没给就是 ××**
- 个人经历：学校/单位/课题组/学历时间线——**用户没给就是（待填）**
- 引用来源：文本里任何 `[N]` 引用标注（正文/图注/脚注）——**deck 必须有真实参考文献表**
  （manifest confirmed_facts 里登记了带作者/年份/期刊的出处），没有 → 删标注。
  且页面来源标注**不得与 manifest 来源层级自相矛盾**（如 manifest 标 L2 实验数据，
  页面却写「数据源 [13]」→ 判编造）
- 数字成果关键词组合：值里"个人成果关键词 + 数字"同现（如 "12 篇一作"、"2 项国自然"、
  "480 引用"）且 manifest 无对应 → 判**编造**（v0.6.2 补的漏检）
- 实验数据：模量/kPa/存活率/阈值——**必须来自 L2 用户数据**；确需外推要在脚注明示"外推需复核"
- 用户给但**未自测复核的数值**（如 L3 口头提供的力学数据）：不得写成既成事实，
  必须带"（数值待复核）"/"（待验证）"限定语，复核后才能去掉
- 封面/页脚单位与作者信息——**用户没给就是（待填）**

## 三、联网补充（L4）的约束

允许用联网补信息，但必须同时满足：
1. **只在用户完全没覆盖的缺口用**（研究背景的常识性统计、药物机制、术语定义等客观事实）
2. **必须是可核实的事实**，不是推测——如"FDA 撤市药物中肝毒性占比"要有出处
3. **必须标注来源**：deck 里对应位置加 `来源脚注`（如 "来源：FDA 官网统计，2023"）
4. **不得用于个人/成果类数据**（论文数、被引量、专利——这些只能用用户给的）

## 四、sources_manifest.json（内容边界清单）

每个 deck 目录下维护 `sources_manifest.json`，记录用户实际提供了什么：

```json
{
  "user": "××（待填）",
  "uploaded_template": "组会模板.pptx",
  "uploaded_docs": ["研究计划.docx", "实验数据.xlsx"],
  "confirmed_facts": [
    {"field": "研究方向", "value": "（待用户确认）", "source": "L2 文档"},
    {"field": "姓名", "value": "××（待填）", "source": "L3 交互"}
  ],
  "placeholders": ["论文数", "被引量", "专利数", "单位", "教育经历"],
  "web_supplemented": [
    {"field": "术语定义", "value": "（示例）", "source": "https://...", "verified": true}
  ]
}
```

`pptagent/honesty.py` 检查器按此清单逐条核对 deck_plan.json：
- 清单里没有、又非占位的数字/头衔/引用 → 判**编造**，报错并给修正建议
- 联网补充项必须有 `source` 且 `verified=true`，否则判为未核实

`source` 字段可带**状态限定语**，区分数据的可信状态，页面照实呈现：
- `L3 交互（用户提供，数值待自测复核）` —— 用户口头给的数值，已入册但未自测确认
- `L2 研究计划（预期成果，非已实现）` —— 计划/预期产出，**不是已实现成果**，页面不得表述为既成事实
- 预期成果、待复核数据都算"有来源"、可上页面；但页面要用脚注/限定语如实标注其状态

## 五、生成流程中的强制环节

1. **首先生成/更新 `sources_manifest.json`**（每次跑 deck 前由用户对话确认补充）
2. **生成前检查器校验**：`python -m pptagent.honesty examples/demo/deck_plan.json examples/demo/sources_manifest.json`
   - 有编造项 → 阻断生成，列出每一项的具体位置与修正
   - v0.6.2 起核对范围：任意文本里的 `[N]` 引用、`个人成果关键词 + 数字` 组合、
     `num/org/role/meta/affil` 字段的裸数字与裸单位
   - **豁免（防误报）**：stat 项的 `label` 描述字段（"近5年一作/共同一作论文"是统计描述，
     数字在 `num` 另查）；已如实登记进 confirmed_facts 的预期成果（"论文 1-2 篇 + 方法专利"）
     确实是 L2 计划内容，不判编造
3. **生成后评审**：评审 agent 的「内容诚实」维度复核（见 REVIEW_LOOP.md 第三视角）
4. **参考材料只做设计规范，绝不进内容**（kimiPPT/报奖PPT 是 L0 设计参考，不是 L1-L4 内容来源）

## 六、诚实≠留白过度

诚实不是让页面空。凡是用户给的（L1-L3）内容要**饱满呈现**——把确认过的研究内容、
实验数据、技术路线做足。占位只用于**用户确实没给**的字段，并在图注/脚注里提示
"待用户提供"。这样 PPT 既诚实又不空。

## 七、验收标准

- deck_plan.json 里每一个数字/头衔/单位/引用都能在 sources_manifest 找到出处，
  或为 `××`/`（待填）` 占位
- 页面上任何数字处于且仅处于三种状态之一：**有来源**（confirmed_facts / verified 联网补充）、
  **占位**（××/待填）、**带限定语**（待复核 / 预期成果·非已实现）
- 联网补充项都带可点击来源，且标 verified
- 没有任何"看起来合理但用户没给"的编造值
